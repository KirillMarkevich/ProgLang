### Задание 1 **(2)**
*Оцените работу следующих фрагментов программ. Какие из них обладают неоднозначным поведением? Почему?*
```
int x=10, y=3;
std::cout << std::min(x=15, x+y);
```
```
int x=10, y=3;
x=15, y+=x, x+=y;
```
```
int x=10, y=9;
if (x>y++ && y++>9)
  cout << "yes" << endl;
cout << y;
```

*Тексты программ разместите в папке с номером задания*

**Решение**

**Первый фрагмент**

```cpp
int x = 10, y = 3;
std::cout << std::min(x = 15, x + y);
```

Поведение зависит от порядка вычисления аргументов `std::min`.

- Если сначала вычисляется `x = 15`, то второй аргумент равен `15 + 3 = 18`, поэтому выводится `15`.
- Если сначала вычисляется `x + y`, то его значение равно `10 + 3 = 13`, после чего `x` становится равным `15`. В этом случае выводится `13`.

В C++17 и более новых стандартах порядок вычисления аргументов функции не определён заранее, но вычисления аргументов упорядочены относительно друг друга: результат может быть `13` или `15`. В стандартах до C++17 изменение `x` и чтение `x` в разных аргументах не были упорядочены, поэтому выражение имеет неопределённое поведение.

**Второй фрагмент**

```cpp
int x = 10, y = 3;
x = 15, y += x, x += y;
```

Здесь запятые являются операторами запятая, которые вычисляют выражения слева направо. Сначала `x = 15`, затем `y += x`, то есть `y = 3 + 15 = 18`, после этого `x += y`, то есть `x = 15 + 18 = 33`. Выражение имеет определённое поведение; в конце `x == 33`, `y == 18`.

**Третий фрагмент**

```cpp
int x = 10, y = 9;
if (x > y++ && y++ > 9)
    cout << "yes" << endl;
cout << y;
```

Постфиксный инкремент возвращает прежнее значение переменной, а затем увеличивает её на единицу. Сначала сравниваются `10 > 9`: условие истинно, `y` становится равным `10`. Поэтому проверяется и вторая часть `&&`: `10 > 9` также истинно, после чего `y` становится равным `11`. Программа выводит:

```text
yes
11
```

Второй операнд `&&` вычисляется только в том случае, если первый операнд истинен. В этом фрагменте поведение определено.

### Задание 2 **(2)**
*Как записать следующие строки программы на С++ в виде одного
выражения? Приведите несколько способов, в том числе с использованием операторов инкремента.*
*Проверьте работу написанных программ*
```
x=x+1;
z=z+2*x+3*y;
y=y+1;
```
*Тексты программ разместите в папке с номером задания*

**Решение**

Чтобы заменить три инструкции одним выражением, можно использовать оператор запятая. Он обеспечивает вычисление частей выражения слева направо, поэтому сначала увеличивается `x`, затем вычисляется новое значение `z` с уже увеличенным `x`, а после этого увеличивается `y`.

Первый вариант:

```cpp
x++, z = z + 2 * x + 3 * y, y++;
```

Второй вариант с префиксным инкрементом и составным присваиванием:

```cpp
(++x, z += 2 * x + 3 * y, ++y);
```

Третий вариант, использующий `+=` для увеличения переменных:

```cpp
(x += 1, z += 2 * x + 3 * y, y += 1);
```

Все три выражения сохраняют порядок исходных операций. Важно, что `x` увеличивается **до** вычисления выражения для `z`, а `y` — **после** него.

### Задание 3 **(2)**
*Рассмотрите следующий фрагмент программы. Он заполняет вектор из 10 элементов единицами.*
```
std::vector<int> x(10);
for (int i = 0; i < 10;)
   x[i++] = 1;
```
*Перепишите ее так, чтобы в третьей строке использовался префиксный инкремент, но результат ее работы не изменился.*
```
std::vector<int> x(10);
for (...)
   x[++i]=1;
```

**Решение**

В исходном варианте `i` начинается с нуля, а выражение `x[i++]` сначала обращается к элементу с текущим индексом, затем увеличивает `i`. При замене постфиксного инкремента на префиксный индекс нужно сдвинуть начальное значение `i` на единицу вниз. Тогда первая итерация увеличит `i` с `-1` до `0` и запишет единицу в `x[0]`, а последняя запишет единицу в `x[9]`.

```cpp
std::vector<int> x(10);
for (int i = -1; i < 9;)
    x[++i] = 1;
```

Цикл выполняется десять раз и заполняет единицами все элементы вектора с индексами от `0` до `9`. В результате вектор такой же, как и в исходной программе.

### Задание 4 **(2)**

*Почему присваивание* ```(++x)=y``` *является синтаксически правильным, а*
```(x++)=y``` - *нет? Запишите текст сообщения об ошибке, переведите и объясните его.*

**Решение**

Префиксный инкремент `++x` увеличивает `x` и возвращает саму переменную как изменяемое lvalue-выражение. Поэтому результат можно использовать слева от оператора присваивания:

```cpp
(++x) = y;
```

Сначала `x` увеличивается на единицу, затем получившемуся значению присваивается `y`.

Постфиксный инкремент `x++` возвращает копию прежнего значения `x`, а не саму переменную. Это значение нельзя использовать в качестве левой части присваивания:

```cpp
(x++) = y; // ошибка
```

Текст сообщения об ошибке:

```text
error: lvalue required as left operand of assignment
```

Перевод: «для левого операнда присваивания требуется lvalue». Иными словами, слева от `=` должно находиться выражение, обозначающее изменяемый объект, а `x++` таким выражением не является.

### Задание 5 **(2)**

*Программисты на Python для обмена значений двух переменных часто пишут строку*
```
a,b = b,a
```
*Проверьте, будет ли аналогичная строка на С++ (с точкой с запятой в конце) являться синтаксически
правильной? Будет ли она обменивать значения переменных? Как в языке С++ вычисляется это выражение?*

**Решение**

Строка

```cpp
a, b = b, a;
```

синтаксически допустима в C++, но не выполняет обмен значениями. В C++ запятая здесь является оператором, а не разделителем элементов кортежа, как в Python. Операторы присваивания имеют более высокий приоритет, чем оператор запятая, поэтому выражение эквивалентно последовательному вычислению:

```cpp
a;
b = b;
a;
```

Первое и последнее выражения лишь обращаются к `a` и не изменяют его. Среднее присваивает переменной `b` её же значение. Следовательно, значения `a` и `b` остаются прежними.

Для обмена значений в C++ можно использовать временную переменную:

```cpp
int temp = a;
a = b;
b = temp;
```

Для переменных подходящего типа также можно применить `std::swap(a, b)`, подключив заголовок `<utility>` или `<algorithm>`.

### Задание 6 **(2)**

*Проверьте работу следующего фрагмента программы*
```
  std::string s;
  for (int i=0; i<1000000; i++)
     s += 'a';
  std::cout << s.size();
```
*Измените третью строку на*
```
s=s+'a';
```
*Изменится ли что-нибудь в ее работе? Объясните результат.*

**Решение**

В исходном варианте символ добавляется к строке оператором `+=`:

```cpp
std::string s;
for (int i = 0; i < 1000000; i++)
    s += 'a';
std::cout << s.size();
```

Если программа успешно завершится, она выведет `1000000`, поскольку в строку добавлено миллион символов.

После замены третьей строки на

```cpp
s = s + 'a';
```

итоговый размер строки останется таким же, и вывод также будет `1000000`. Однако эффективность работы может существенно ухудшиться. Выражение `s + 'a'` создаёт новую строку на основе текущей строки и добавляет к ней символ, а затем результат присваивается `s`. На каждой итерации приходится обрабатывать уже накопленную строку. В результате суммарный объём копирования может вырасти примерно пропорционально квадрату числа добавляемых символов.

Оператор `+=` обычно добавляет символ непосредственно в строку и благодаря резервированию памяти работает значительно эффективнее. Поэтому различие заключается прежде всего во времени выполнения и количестве операций с памятью, а не в конечном результате.

### Задание 7 **(2)**

*Как работает следующая программа? Как зависит результат от исходного значения?*
```
int x;
std::cin >> x;
x-->0 && x-->0 && x-->0 && x-->0 && x-->0;
std::cout << x;
```

**Решение**

Запись `x-->0` разбирается как `x-- > 0`: это постфиксный декремент `x--` и сравнение его прежнего значения с нулём. При этом `x` уменьшается на единицу даже тогда, когда сравнение оказывается ложным.

Оператор `&&` вычисляет выражения слева направо и прекращает вычисление после первого ложного условия. Поэтому программа выполняет не более пяти сравнений и выводит конечное значение `x`.

Если исходное значение обозначить `n`, результат будет таким:

- при `n >= 4` выполняются все пять декрементов, и выводится `n - 5`;
- при `0 <= n <= 3` выполнение останавливается на первом сравнении с прежним значением `x`, равным нулю, и выводится `-1`;
- при `n < 0` первое сравнение сразу ложно, но постфиксный декремент всё равно выполняется, поэтому выводится `n - 1`.

Например, при вводе `7` программа выводит `2`, а при вводе `2` — `-1`.

### Задание 8 **(3)**

*Какое число выводит следующий фрагмент программы? Посчитайте результат без использования
вычислительной техники. Отчет должен содержать процесс вычислений.*
```
int s = 0;
for (int i = 0, j = 5;i+j <= 16;(i<j ? i : j)++)
   (s += i) += j;
std::cout << s;
```

**Решение**

Начальные значения: `i = 0`, `j = 5`, `s = 0`. Тело цикла

```cpp
(s += i) += j;
```

сначала прибавляет `i` к `s`, а затем прибавляет `j` к тому же `s`. Поэтому за одну итерацию сумма увеличивается на `i + j`.

Выражение изменения цикла `(i < j ? i : j)++` увеличивает меньшую из двух переменных; если `i` и `j` равны, увеличивается `j`. Последовательность пар `(i, j)` и прибавляемых значений получается следующей:

| `i` | `j` | `i + j` | Значение `s` после итерации |
|---:|---:|---:|---:|
| 0 | 5 | 5 | 5 |
| 1 | 5 | 6 | 11 |
| 2 | 5 | 7 | 18 |
| 3 | 5 | 8 | 26 |
| 4 | 5 | 9 | 35 |
| 5 | 5 | 10 | 45 |
| 5 | 6 | 11 | 56 |
| 6 | 6 | 12 | 68 |
| 6 | 7 | 13 | 81 |
| 7 | 7 | 14 | 95 |
| 7 | 8 | 15 | 110 |
| 8 | 8 | 16 | 126 |

После последней показанной итерации `i` и `j` становятся равными `8` и `9`. Условие `i + j <= 16` превращается в `17 <= 16` и становится ложным, поэтому цикл завершается.

**Ответ:**

```text
126
```

###  Задание 9 **(3)**
*Рассмотрите следующую программу. Предполагается, что на вход подается некоторый
индекс в массиве - число от нуля до девяти и значение, которое надо записать по этому индексу.*
```
int i = 0;
std::vector<int> x(10);
std::cin >> i >> x[i];
std::cout << x[i];
```
*Проверьте работу этой программы на различных компиляторах. Найдите два компилятора (можно 
проверить онлайн компиляторы), на которых эта программа будет давать различные ответы при одинаковом
вводе. Как это объяснить?*

**Решение**

Проблема заключается в выражении:

```cpp
std::cin >> i >> x[i];
```

Оно последовательно записано как цепочка операторов извлечения из потока. Для правильной работы сначала необходимо считать значение `i`, а затем использовать его как индекс `x[i]`.

В стандартах C++ до C++17 порядок вычисления операндов оператора сдвига, перегруженного здесь для потокового ввода, не гарантировал, что чтение `i` будет завершено до вычисления индекса `x[i]`. Из-за этого изменение `i` при вводе и чтение `i` для индекса могли оказаться неупорядоченными, что приводит к неопределённому поведению. В таком случае результат может различаться между компиляторами или настройками стандарта, и полагаться на конкретный вывод нельзя.

Начиная с C++17 левый операнд оператора `>>` вычисляется раньше правого. Поэтому при использовании соответствующего стандарта C++ ввод `i` завершается до вычисления `x[i]`, и программа работает ожидаемым образом для индекса от `0` до `9`.

Надёжный вариант — разделить ввод на две инструкции:

```cpp
int i = 0;
std::vector<int> x(10);
std::cin >> i;
std::cin >> x[i];
std::cout << x[i];
```

Такой код явно обеспечивает необходимый порядок действий. При проверке на компиляторах следует указывать стандарт языка (например, C++14 и C++17): различия могут быть связаны не только с компилятором, но и с выбранным стандартом.
