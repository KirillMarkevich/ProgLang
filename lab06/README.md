### Задание 1 **(3)**
*Рассмотрим следующую программу на С++.*
```
#include <iostream>
#include <cmath>
int main() {
   double x = 0;
   const auto Pi = std::acos(0) * 2;
   std::cout << Pi << std::endl;
   return 0;
}
```
*Проверьте четыре способа объявления* **Pi**.
* ```const auto Pi = acos(0) * 2;```
* ```constexpr auto Pi = std::acos(0) * 2;```
* ```const auto Pi = acos(x) * 2;```
* ```constexpr auto Pi = std::acos(x) * 2;```

*Что можно сказать об этих вариантах? Проверьте, в каких вариантах объявляется константа этапа трасляции.*

*Тексты программ разместите в папке с номером задания*


**Решение**

Проверять варианты следует с учётом версии стандарта C++. В распространённых стандартах до C++23 функции `std::acos` не являются `constexpr`, поэтому вызов `acos`/`std::acos` нельзя использовать для вычисления значения `constexpr` во время компиляции.

1. `const auto Pi = acos(0) * 2;` — объявляется константный объект типа `double`. Его значение вычисляется при выполнении программы; само по себе `const` не гарантирует, что значение является константным выражением времени компиляции.
2. `constexpr auto Pi = std::acos(0) * 2;` — в стандартных реализациях до C++23 не компилируется: вызов `std::acos` не является допустимым константным выражением. В стандарте C++26, где соответствующие математические функции поддерживают вычисление на этапе компиляции, результат зависит от поддержки этого стандарта компилятором.
3. `const auto Pi = acos(x) * 2;` — объявляется константный объект, значение которого вычисляется во время выполнения на основе `x`. Это не константа этапа трансляции.
4. `constexpr auto Pi = std::acos(x) * 2;` — в стандартных реализациях до C++23 не компилируется из-за `std::acos`; кроме того, `x` — обычная переменная, а не константное выражение, поэтому её значение нельзя использовать для инициализации `constexpr`.

Для распространённых стандартов C++17/20/23 ни один из этих вариантов не создаёт константу этапа трансляции: варианты 1 и 3 компилируются, но вычисляются во время выполнения, а варианты 2 и 4 не проходят компиляцию. Для надёжной константы этапа трансляции можно, например, использовать `constexpr double Pi = 3.14159265358979323846;`.


### Задание 2 **(2)**
*Проверьте работу следующей программы на С++*
```
#include <iostream>
int main() {
   {
      int x, y;
      std::cin >> x >> y;
      std::cout << x+y << std::endl;
   }
   {
      double x, y;
      std::cin >> x >> y;
      std::cout << x+y << std::endl;
   }
   return 0;
}
```
*Нужны ли в этой программе вложенные фигурные скобки? Дайте подробный ответ с объяснением причин.*


**Решение**

Да, в этой программе внутренние фигурные скобки нужны для сохранения двух отдельных областей видимости. В первом блоке объявляются `int x, y`, а во втором — `double x, y`. Имена переменных могут повторяться, потому что первые переменные перестают существовать в области видимости после закрывающей скобки первого блока.

Если убрать скобки, все четыре объявления окажутся в одной области видимости. Повторно объявить `x` и `y` с другими типами в этой области нельзя — программа не скомпилируется. Можно было бы обойтись без вложенных блоков, если переименовать переменные, например в `intX`, `intY`, `doubleX`, `doubleY`, но при текущих одинаковых именах скобки необходимы. Они также ограничивают время жизни локальных переменных соответствующим блоком.


### Задание 3 **(2)**
*Проверьте работу следующего фрагмента программы на С++.*
```
int s = 0;
for (int i = 0; i < 4; i++) {
   for (int i = 0; i < 3; i++) {
      s += i;
   } 
   s += i; 
}
std::cout << s;
```
*В результате каких вычислений был получен ответ? Дайте подробный ответ.*


**Решение**

В C++ переменная `i` во внутреннем цикле — отдельная переменная, которая скрывает переменную `i` внешнего цикла. После завершения внутреннего цикла внутренняя `i` выходит из области видимости, и выражение `s += i` использует внешнюю `i`.

При каждом из четырёх проходов внешнего цикла внутренний цикл добавляет к `s` значения `0`, `1` и `2`, то есть `0 + 1 + 2 = 3`. За четыре прохода это `4 × 3 = 12`. Затем внешний цикл добавляет значения внешней `i`: `0 + 1 + 2 + 3 = 6`. Итого `s = 12 + 6 = 18`, поэтому программа выводит `18`.


### Задание 4 **(2)**

*Проверьте работу следующего фрагмента программы на* **Python**.
```
s = 0
for i in range(4):
   for i in range(3):
      s += i
   s += i
print(s)
```
*В результате каких вычислений был получен ответ? Дайте подробный ответ.*

*На основе этих примеров поясните различия между* **С++** и **Python** *при работе с переменными*.


**Решение**

В Python циклы `for` не создают отдельную область видимости для переменной цикла. Поэтому внутренний цикл использует то же имя `i`, что и внешний, и после завершения внутреннего цикла `i` остаётся равной `2` — последнему значению из `range(3)`.

На каждом из четырёх проходов внутренний цикл прибавляет `0 + 1 + 2 = 3`, всего `4 × 3 = 12`. После каждого внутреннего цикла команда `s += i` дополнительно прибавляет `2`; это происходит четыре раза, то есть добавляется `4 × 2 = 8`. Итог: `s = 12 + 8 = 20`, программа выводит `20`.

**Различие C++ и Python:** в C++ переменная, объявленная в заголовке внутреннего цикла, имеет область видимости внутри этого цикла и скрывает внешнюю переменную с тем же именем. После цикла снова доступна внешняя `i`. В Python переменная цикла не ограничена отдельной областью видимости, поэтому внутренний цикл перезаписывает `i`, и после него доступно последнее присвоенное значение.


### Задание 5 **(2)**

*Напишите свой пример программы на* **С++**, *создающий и использующий пространства имен. Программа
должна содержать не менее двух пространств имен.*


**Решение**
```cpp
#include <iostream>

namespace Geometry {
    double rectangleArea(double width, double height) {
        return width * height;
    }
}

namespace Text {
    void printResult(double value) {
        std::cout << "Площадь прямоугольника: " << value << '\n';
    }
}

int main() {
    double area = Geometry::rectangleArea(5.0, 3.0);
    Text::printResult(area);
    return 0;
}
```
В программе используются два пространства имён: Geometry и Text. Пространство имён Geometry содержит функцию rectangleArea(), которая вычисляет площадь прямоугольника умножением ширины на высоту. Пространство имён Text содержит функцию printResult(), которая выводит результат на экран.

В функции main() сначала вычисляется площадь прямоугольника со сторонами 5 и 3, затем полученное значение передаётся функции вывода. Оператор :: используется для обращения к функциям, находящимся в определённых пространствах имён. Это помогает разделять код и избегать конфликтов имён.


### Задание 6 **(2)**

*Рассмотрим следующий фрагмент программы. Эта программа 1000000 раз обменивает значения двух длинных 
строк с использованием третьей строки. Проверьте, насколько быстро она работает.*

```
std::string a(100000, 'a');
std::string b(100000, 'b');
for (int i=0;i<1000000;i++) {
   std::string c(a);
   a = b;
   b = c;
}
std::cout << a[0] << b[0];
```
*Попробуйте использовать для обмена значений строк функцию* **swap**. 
*Проверьте, изменилось ли время работы. В чем ошибка исходной программы?
Исправьте исходную программу, чтобы ускорить ее работу. Изменения не должны 
затрагивать общий вид программы (присваивания, использование временной переменной).*


**Решение**

Время работы уменьшилось в 5,5 раза: с 6.449 до 1.168 секунды. В исходном варианте на каждой итерации создаётся копия строки `a` длиной 100 000 символов, затем содержимое `b` копируется в `a`, а содержимое временной строки `c` — в `b`. При миллионе итераций выполняется огромное количество копирований символов и выделений/освобождений памяти, поэтому программа работает медленно.

Функция `swap` меняет местами внутренние ресурсы строк, не копируя все символы.

```cpp
#include <iostream>
#include <string>

int main() {
    std::string a(100000, 'a');
    std::string b(100000, 'b');

    for (int i = 0; i < 1000000; i++) {
        std::string c;
        c.swap(a);
        a.swap(b);
        b.swap(c);
    }

    std::cout << a[0] << b[0];
    return 0;
}
```

Временная строка `c` изначально пуста, а обмены через `swap` переставляют строки без копирования их содержимого. Это существенно быстрее исходного варианта. После нечётного числа обменов `a` начинается с `'b'`, а `b` — с `'a'`, поэтому результат — `ba`.

Ошибка исходной программы не в корректности результата, а в неэффективном алгоритме: копирование длинных строк повторяется миллион раз.


### Задание 7 **(2)**

*Рассмотрим программу на языке* **Python**.
```
a = 'Hello world'
print(a, id(a))
b = a
print(b, id(b))
a += ' and goodbye'
print(a, id(a))
print(b, id(b))
```
*Объясните ее работу. В какой момент создавались строки? 
Что означает значение, возвращенное функцией* **id**?


**Решение**

После первой строки создаётся строковый объект со значением `Hello world`, и переменная `a` ссылается на него. В команде `print(a, id(a))` выводятся значение строки и её идентификатор.

При выполнении `b = a` новая строка не создаётся: `b` начинает ссылаться на тот же объект, что и `a`. Поэтому значения `id(a)` и `id(b)` совпадают.

Строки в Python неизменяемы. Выражение `a += ' and goodbye'` создаёт новую строку со значением `Hello world and goodbye` и связывает имя `a` с новым объектом. Имя `b` продолжает ссылаться на прежнюю строку `Hello world`. Поэтому два последних вывода показывают разные значения и, как правило, разные идентификаторы.

Функция `id()` возвращает идентификатор объекта, уникальный среди объектов, время жизни которых пересекается. В CPython этот идентификатор обычно соответствует адресу объекта в памяти, однако язык Python не гарантирует, что `id()` всегда является адресом памяти.


### Задание 8 **(2)**

*Пусть* **a** - *строковая переменная в программе на* **Python**.
*Есть ли разница между работой присваивания*
```b = a```
и
```b = a[:]```
*Напишите программу для демонстрации различий.*


**Решение**

Для строки `b = a` имя `b` связывается с тем же объектом, что и `a`. Выражение `b = a[:]` создаёт срез всей строки; результат равен исходной строке. Поскольку строки неизменяемы, Python может вернуть тот же объект, и полагаться на различие идентификаторов нельзя. Поэтому для строк эти варианты не дают надёжно наблюдаемого различия в поведении.

Программа для демонстрации:

```python
a = "hello"
b = a
c = a[:]

print(a, id(a))
print(b, id(b))
print(c, id(c))

print(a == b == c)
```

Все три значения равны. В конкретной реализации `id` может совпасть у всех переменных; это не ошибка, а допустимое поведение Python. Чтобы наглядно увидеть разницу между присваиванием и копированием, обычно используют изменяемый объект, например список:

```python
a = [1, 2, 3]
b = a
c = a[:]

a.append(4)
print(b)
print(c)
```

Во втором примере срез списка создаёт новый список, поэтому изменение исходного списка не меняет `c`.


###  Задание 9 **(3)**
*Напишите программу на языке* **Python**, *которая создаст 2600 переменных с именами
от* **a0** *до* **a99**, *от* **b0** *до* **b99** *и так далее, от* **z0** *до* **z99**. 
*Присвойте всем переменным различные значения от 1 до 2600.*


**Решение**

```python
import string

value = 1
for letter in string.ascii_lowercase:
    for number in range(100):
        globals()[f"{letter}{number}"] = value
        value += 1

print(a0, a99, b0, z99)
print(len([
    name for name in globals()
    if len(name) >= 2
    and name[0] in string.ascii_lowercase
    and name[1:].isdigit()
    and 0 <= int(name[1:]) <= 99
]))
```
