### Задание 1 **(2)**
*Переведите в двоичную запись два произвольных рациональных числа (числа вида* $\frac{p}{q}$).
*У одного из чисел знаменатель должен быть степенью двойки (32), а у другого --- некоторым числом
от 9 до 12.*

*Запись второго числа будет содержать период. Его надо найти. При решении задачи нельзя 
использовать вычислительную технику. Процесс решения должен быть представлен в отчете.*


**Решение**

1. Возьмём число $\frac{5}{32}$. Поскольку знаменатель $32=2^5$, двоичная дробь конечна:
$\frac{5}{32}=\frac{4}{32}+\frac{1}{32}=\frac{1}{8}+\frac{1}{32} =0.00101_2.$

2. Возьмём число $\frac{1}{10}$. Последовательно умножаем дробную часть на 2, каждый раз записывая целую часть результата:

1. $0{,}1\cdot2=0{,}2$ — бит 0.
2. $0{,}2\cdot2=0{,}4$ — бит 0.
3. $0{,}4\cdot2=0{,}8$ — бит 0.
4. $0{,}8\cdot2=1{,}6$ — бит 1, остаток $0{,}6$.
5. $0{,}6\cdot2=1{,}2$ — бит 1, остаток $0{,}2$.

После пятого шага остаток $0.2$ повторился, поэтому дальше повторяются биты $0011$. Следовательно,
$\frac{1}{10}=0.0001100110011\ldots_2 =0.0001\overline{1001}_2.$
Период — $1001$ (после начальных нулей запись также можно представить как $0.00011\overline{0011}_2$).


### Задание 2 **(3)**
*Переведите в двоичную запись и найдите машинное представление в типе* **double**
*для произвольного вещественного числа большего, чем 100 с одним знаком после точки, например
для* $113.7$. *Цифра после точки не должна быть нулем иля пятеркой.*

*При решении задачи нельзя 
использовать вычислительную технику. Процесс решения должен быть представлен в отчете.*


**Решение**

Возьмём число $123.7$. Целая часть переводится делением на 2:
$123_{10}=1111011_2.$
Для дробной части последовательно умножаем на 2:

1. $0{,}7\cdot2=1{,}4$ — бит 1, остаток $0{,}4$.
2. $0{,}4\cdot2=0{,}8$ — бит 0.
3. $0{,}8\cdot2=1{,}6$ — бит 1, остаток $0{,}6$.
4. $0{,}6\cdot2=1{,}2$ — бит 1, остаток $0{,}2$.
5. $0{,}2\cdot2=0{,}4$ — бит 0.

Остаток $0.4$ повторяется, поэтому далее повторяется блок $0110$:
$123.7_{10}=1111011.101100110011\ldots_2 =1.111011101100110011\ldots_2\cdot2^6.$

В формате IEEE 754 **double** знак равен 0, смещённый порядок равен $6+1023=1029$, то есть $10000000101_2$. После ведущей единицы записываются 52 бита дробной части; бесконечная двоичная дробь округляется до ближайшего представимого значения. Получаем:

- знак: `0`;
- порядок: `10000000101`;
- дробная часть мантиссы: `1110111011001100110011001100110011001100110011001101`.

Полное 64-битное представление:
```text
0 10000000101 1110111011001100110011001100110011001100110011001101
```
В шестнадцатеричном виде это `0x405EECCCCCCCCCCD`. Поэтому значение `double` не равно математически точному $123.7$, а является ближайшим к нему представимым числом.


### Задание 3 **(3)**
*Найдите сумму и произведение для записанных далее пар чисел. Числа заданы в двоичной записи 
в экспоненциальном виде. Ответ необходимо записать в нормализованннои экспоненциальном виде.*

* 1.0011e18 и $1.1001e21;
* 1.1011e-25 и, $1.1101e-23;
* 1.1011e-3 и $1.1011e1.
  
*При решении задачи нельзя 
использовать вычислительную технику. Процесс решения должен быть представлен в отчете.*


**Решение**

Считаем, что $e k$ означает умножение на $2^k$. При сложении приводим слагаемые к общему порядку, а при умножении перемножаем мантиссы и складываем показатели степеней.

**1.** $1.0011_2\cdot2^{18}$ и $1.1001_2\cdot2^{21}$.

Сумма:
$(0.0010011_2+1.1001000_2)\cdot2^{21} =1.1011011_2\cdot2^{21}.$
Произведение:
$(1.0011_2\cdot1.1001_2)\cdot2^{18+21} =1.11011011_2\cdot2^{39}.$

**2.** $1.1011_2\cdot2^{-25}$ и $1.1101_2\cdot2^{-23}$.

Сумма:
$(0.011011_2+1.110100_2)\cdot2^{-23} =10.001111_2\cdot2^{-23} =1.0001111_2\cdot2^{-22}.$
Произведение:
$(1.1011_2\cdot1.1101_2)\cdot2^{-48} =11.00001111_2\cdot2^{-48} =1.100001111_2\cdot2^{-47}.$

**3.** $1.1011_2\cdot2^{-3}$ и $1.1011_2\cdot2^1$.

Сумма:
$(0.0011011_2+1.1011000_2)\cdot2^1 =1.1110011_2\cdot2^1.$
Произведение:
$(1.1011_2)^2\cdot2^{-2} =10.11011001_2\cdot2^{-2} =1.011011001_2\cdot2^{-1}.$


### Задание 4 **(2)**

*Рассмотрим следующий пример в IDLE Python*
```
>>> x = 99.99
>>> int(x/10+0.001)
9
```
*Результат должен был быть равен 10, однако оказался другим. Почему так произошло?
Как исправить программу, чтобы она корректно переводила вещественные числа в целые?*


**Решение**

Число `99.99` в двоичном формате `double` хранится приближённо. Кроме того, вычисление `x/10 + 0.001` также выполняется с округлением. Поэтому вместо математически ожидаемого `10.0` может получиться число немного меньше 10 (например, `9.999999999999998`). Функция `int()` отбрасывает дробную часть, а не округляет, поэтому результатом становится `9`.

```python
x = 99.99
print(round(x / 10 + 0.001))
```


### Задание 5. **(2)**

*Рассмотрите следующую программу. Объясните результаты ее работы. В частности,
как величина* $y$ *повлияла на ответ?*
```
x = 1/3
y = 1
for i in range(20):
    print((x+y)-y)
    y*=10
```
*В отчете требуется привести вычисления для оценки погрешности.*


**Решение**

Число `x = 1/3` в `float` хранится приближённо, поскольку его двоичная запись бесконечна. В каждом цикле вычисляется сначала `x + y`, а затем из результата вычитается `y`. Когда `y` велико, прибавление `x` частично или полностью теряется при округлении суммы. При вычитании `y` это потерянное значение уже не восстанавливается.

Для стандартного Python с IEEE 754 `double` результат постепенно отклоняется от $1/3$, а при `y = 10^16` и далее становится `0.0`. Например, получаются следующие значения:

- при $y=1$: `0.33333333333333326`;
- при $y=10^8$: `0.3333333283662796`;
- при $y=10^{12}$: `0.3333740234375`;
- при $y=10^{14}$: `0.328125`;
- при $y=10^{15}$: `0.375`;
- при $y=10^{16}$: `0.0`.

**Оценка погрешности.** Для `double` единичная относительная погрешность округления обычно оценивается величиной $u=2^{-53}\approx1.11\cdot10^{-16}$. При сложении чисел порядка $y$ абсолютная погрешность округления имеет порядок $u|y|$ (точная граница зависит от шага между соседними числами около $y$). После вычитания двух близких чисел ошибка не исчезает, а становится заметной относительно небольшого результата. Когда шаг между представимыми числами около $y$ превышает величину $x$, прибавление $x$ может вообще не изменить `y`; тогда `(x+y)-y` равно нулю.


### Задание 6 **(2)**

*Для какого минимального значения* $n$ *программа на С++ выведет* **inf**? *Объясните
ответ.* *Что произойдет, если тип* **double** *заменить на* **long double**?
```
int n=...;
double s = pow(2, n);
std::cout << std::fixed << s << std::endl;
```


**Решение**

Для типа IEEE 754 `double` наибольшая конечная степень двойки — $2^{1023}$. Число $2^{1024}$ уже превышает максимальное конечное значение, поэтому при вычислении `pow(2, n)` для минимального целого $n=1024$ получается положительная бесконечность `inf`.

Если заменить `double` на `long double`, результат зависит от реализации компилятора и платформы: диапазон `long double` не одинаков на всех системах. Например, в распространённом формате x86 extended precision максимальный показатель степени равен 16383, и первая такая степень двойки, которая переполняется, — $2^{16384}$. На системах, где `long double` совпадает по формату с `double`, порог останется тем же.


### Задание 7 **(2)**

*Допишите что-либо вместо многоточия программе на С++, чтобы программа при запуске выдавала ответ* **yes**.
```
double s = ...;
if (s != s)
  std::cout << "yes";
```

**Решение**

```cpp
#include <limits>
#include <iostream>

int main() {
    double s = std::numeric_limits<double>::quiet_NaN();
    if (s != s)
        std::cout << "yes";
}
```


### Задание 8 **(2)**

*Какое минимальное натуральное число при преобразовании в тип* **double** *записывается с погрешностью? Объясните
ответ. Почему следующее за ним число уже выводится без погрешности?*

**Решение**

В формате IEEE 754 `double` имеется 53 значащих двоичных разряда (52 бита хранятся явно и ещё одна единица подразумевается для нормализованных чисел). Поэтому все целые числа от 0 до $2^{53}$ включительно представимы точно, но не все целые числа больше этой границы.

Минимальное натуральное число, которое при преобразовании в `double` теряет точность, —
$2^{53}+1=9007199254740993.$
Оно округляется до `9007199254740992` (то есть до $2^{53}$). Следующее целое число,
$2^{53}+2=9007199254740994,$
уже представимо точно: при таких величинах шаг между соседними числами `double` равен 2, поэтому каждое второе целое число представимо, включая это.

###  Задание 9 **(2)**
*Напишите программу для решения следующей задачи.*

*Даны четыре рациональных числа. (Рациональное число - это число вида*
$\frac{p}{q}$, *где* $p$ *и* $q$ - *целые числа.) Напишите программу, которая сравнит сумму
двух первых чисел с суммой двух последних чисел. Программа должна выводить* $1$, $0$ *или* $-1$
*в зависимости от результатов сравнения. Решение можно проверить в проверяющей системе*
[http://olymp3.isu.ru/cgi-bin/new-client?contest_id=102](http://olymp3.isu.ru/cgi-bin/new-client?contest_id=102), *задача 03*.


**Решение**

```cpp
#include <iostream>
using namespace std;

int main() {
    long long p1, q1, p2, q2, p3, q3, p4, q4;
    cin >> p1 >> q1 >> p2 >> q2 >> p3 >> q3 >> p4 >> q4;

    __int128 left_num = (__int128)p1 * q2 + (__int128)p2 * q1;
    __int128 left_den = (__int128)q1 * q2;

    __int128 right_num = (__int128)p3 * q4 + (__int128)p4 * q3;
    __int128 right_den = (__int128)q3 * q4;

    __int128 left = left_num * right_den;
    __int128 right = right_num * left_den;

    if (left > right) cout << 1 << '\n';
    else if (left < right) cout << -1 << '\n';
    else cout << 0 << '\n';

    return 0;
}
```
